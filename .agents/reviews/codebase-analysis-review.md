# Codebase Analysis: codebase

**Scope**: whole codebase; 61 source and config files, 10,428 lines, read in full (`app/`, `lib/`, `eval/*.ts`, the three `expected.yaml`, `.claude/skills/verify/scripts/`, and the compiler, linter, bundler, package and CI configuration). Not judged: prose documents (`docs/`, `.agents/`, `README.md`), the three committed `capture.json` fixtures, the `eval/fixtures/*.html` test pages, `app/distill-theme.css`, `Dockerfile`, `verify.sh`.
**Guides**: `ts-best-practices` (all eight rules, from `references/patterns.md`); `react-best-practices` (async, bundle, rerender, js, and the rules `client-swr-dedup`, `rendering-conditional-render`, `rendering-hoist-jsx`, `rendering-content-visibility`, `rendering-usetransition-loading`). Not read, because the code has nothing of them: the `useeffect-` and `advanced-` categories (no effect, ref or memo exists in `app/`), the event-listener and localStorage rules, and the SVG rules. The React guide states that it is filtered for client-only React + Vite; here it was applied to the one client component (`app/page.tsx`), and its `async-` and `js-` rules to the server-side `lib/` code.
**Commit**: f10ae51
**Recommendation**: NEEDS CHANGES

## Summary

The codebase is in good shape against both guides: `strict` is on, there is no `any` and no suppression comment, model output is always gated by Zod, the page has no effects, and the route's client bundle is 5.39 kB. The largest gain is at the two unvalidated boundaries of `POST /api/analyze`: the request body is typed by assertion, so malformed JSON throws out of the handler (H1), and the response has no shared type, so the client re-declares it and has already drifted (M1, M2, M3). The second group is latency on the URL path: two model round-trips and the cross-origin stylesheet fetches run one after the other (M5, M6).

### High
- **H1** `app/api/analyze/route.ts:96` — The result of `JSON.parse` (`any`) is assigned to `AnalyzeBody` with no validation, so the declared types of `url`, `images` and `mode` are claims that nothing checks. **Rule:** ts-best-practices: `unknown` over `any` ("External data is always `unknown`"), and No `as` casts ("Validate at boundaries… Prefer Zod"). **Why:** a probe that called `POST` directly showed three bodies that throw a `TypeError` out of the handler, because lines 104 and 120 run before either `try` (132, 144): `null` ("Cannot read properties of null (reading 'url')"), `{"url":123}` ("body.url?.trim is not a function"), and `{"images":[null]}` ("Cannot read properties of null (reading 'data')"). The handler throws, so the reply is the framework's own 500 and not the route's JSON error shape. `{"images":"abc"}` and `{"images":[{"data":5}]}` get the generic 502 "internal error" where a 400 belongs. By reading: an unknown `mode` such as `"x"` is accepted, skips both the AI enrichment and the structure lane (`lib/analyze.ts:353`, `route.ts:200`), and the degraded 200 is cached. **Fix:** parse the body as `unknown` and validate it with a Zod schema (Zod is already a dependency): `url` and `image` as optional strings, `images` as an optional array of `{ data: string, name?: string }`, `mode` as `z.enum(["tokens", "structure", "both"]).default("both")`, `forceRefresh` as an optional boolean. Answer a failed `safeParse` with a 400 that names the field. Export the inferred mode type and use it in `lib/analyze.ts:185` and `:335` in place of the repeated literal union. (#170)

The error replies at `route.ts:89`, `:99` and `:115` omit `ok`, while those at `:137`, `:241`, `:246` and `:257` carry `ok: false`. A reply that is not JSON (the platform's 504 when `maxDuration = 60` is exceeded, or the 500 of H1) makes `res.json()` throw, and line 161 shows the user the parser's own message ("Unexpected token…"). `AnalyzeResponse` is a bag of seven optional fields, so line 145 must test `!res.ok || !data.ok || !data.report` and lines 149-158 need a fallback for every field. **Fix:** declare the contract once in a type-only module that both sides import: `AnalyzeResponse = { ok: true; report; markdown; structureReport: StructureReport | null; structureUnavailableReason?; refinements: RefinementChange[]; meta } | { ok: false; error: string }`. Check each payload in `route.ts` with `satisfies`, give every error reply `ok: false`, and move `MAX_IMAGES` (declared in both `page.tsx:49` and `route.ts:21`) into that module. On the client, read the reply as text or guard `res.json()`, then narrow on `ok`. (#171)
- **M2** `app/page.tsx:423` — The AI lane's status reads "skipped (no key)", and the setup hint of line 427 tells the user to set a key, whenever `meta.aiApplied` is false, which also happens when a key is set and the model failed. **Rule:** ts-best-practices: Impossible states ("the type is too loose"). **Why:** `aiApplied` is `Boolean(enriched.report.identity)` (`lib/analyze.ts:293`, `:370`), and `enrichWithAI` returns the same value for "no key" (line 143) and for "two failed attempts" (line 150). A rate-limited or failing model therefore shows a false statement and a hint that cannot help; the structure lane already avoids this with `structureUnavailableReason`. The string dates from the first commit (4936522), before the failure path existed. **Fix:** return the lane's outcome from `enrichWithAI` as a literal union (`"applied" | "no-key" | "failed" | "not-requested"`), carry it in `meta` in place of the boolean, and render one label per value, with the setup hint only for `"no-key"`. Update the assertion in `.claude/skills/verify/scripts/drive.ts:129`. (#172)
- **M3** `app/page.tsx:77` — One request lifecycle is held in eight separate `useState` calls (lines 77-84), so combinations that cannot occur still compile and the render must ask for them. **Rule:** ts-best-practices: Impossible states (the guide's own `{ loading, data?, error? }` example). **Why:** the guards are `status === "done" && report && meta` (lines 342, 348) and `status === "error" && error` (line 335); `analyze` makes eight calls to reset the state (117-124) and seven to fill it (148-159); a success reply without `meta` would end in `status: "done"` with an empty screen and no error. Because the result does not own its inputs, `deriveHost` (line 170) reads the live form: after an image analysis, switching to the URL tab makes the download name `distill-report.md`, and removing the first thumbnail makes it another image's name. **Fix:** hold one value, `{ status: "idle" } | { status: "loading" } | { status: "error"; message: string } | { status: "done"; result: AnalyzeSuccess; sourceName: string }`, set it once per transition, and derive the download name from `result` (`meta.finalUrl`, or `report.source.ref` for images). (#173)
- **M4** `lib/extract/styleDump.ts:609` — The in-page style walker returns through `as unknown as StyleDump`, and inside it every record is a `Record<string, unknown>` (lines 369, 372, 523), so the compiler checks nothing between the collector and `NodeStyle`. **Rule:** ts-best-practices: No `as` casts, and `unknown` over `any`. **Why:** `scanRules` comes out of `new Function(...)` as an implicit `any` (lines 579, 636), which is why its callbacks and the merge loop carry hand-written annotations (594, 595, 673, 698, 704, 722). A field that is renamed or misspelt here compiles, arrives as `undefined`, and is then treated as "nothing observed", so the lane disappears from the report without an error; `npm run eval` replays frozen captures and cannot see it. `lib/extract/structure/harvester.ts:80` shows the typed form in the same codebase: its in-page function returns `RawHarvestNode` and needs no cast. **Fix:** type the records in place (`const record: NodeStyle`, `const nodes: NodeStyle[]`, `const colors: NodeStyle["colors"]`), let `page.evaluate` infer `StyleDump & { crossOriginHrefs?: string[] }`, and annotate `const { scanRules }: ReturnType<typeof createStateScanner>`. Types are erased, so the serialized function does not change. (#174)
- **M5** `app/api/analyze/route.ts:205` — On the URL path the two model round-trips run in series: `analyzeUrl` awaits `enrichWithAI` (`lib/analyze.ts:354`), and only then does the route start the structure lane, whose Stage 7 makes the second call (`lib/extract/structure/structureAI.ts:205`). **Rule:** react-best-practices: `async-dependencies` (Eliminating Waterfalls, the guide's top category). **Why:** the labelling call needs nothing from the enriched report; only Stages 8a and 8b do (`regionMetrics.ts:109`, `tokenLink.ts:36`). Every URL analysis with a key therefore pays one model round-trip more than it must, inside `maxDuration = 60`. The image path already runs its two calls under `Promise.all` (`lib/analyze.ts:239`). The duration was not measured, because it needs an API key. **Fix:** split `extractStructure` into the part up to Stage 7 and the part after it, start the first part together with `enrichWithAI`, and run the second part with the enriched report when both have settled. (#175)
- **M6** `lib/extract/styleDump.ts:622` — Cross-origin stylesheets are fetched one at a time inside a `for` loop, with no timeout, and the whole loop runs twice per analysis. **Rule:** react-best-practices: `async-parallel`. **Why:** `collectStyleDump` is called for the light render (`lib/ingest.ts:305`) and again for the dark one (`:176`), and `APIRequestContext` has no cache, so each sheet is downloaded twice. The installed Playwright (1.61.1) documents the default request timeout as 30 s, so two stalled hosts consume the route's whole 60 s. A site that serves its CSS or web fonts from another origin takes this path on every analysis. Not measured: the fixtures have no cross-origin sheet. **Fix:** fetch all hrefs with `Promise.all` and an explicit timeout of a few seconds, then apply the results in order; pass the fetched CSS text of the first pass into the second. (#176)
- **M7** `lib/interpret.ts:52` — `OUTPUT_SCHEMA`, the hand-written JSON Schema copy of `aiResponseSchema`, has drifted from it. **Rule:** outside the guides. **Why:** Zod requires 3 to 6 adjectives, a non-empty archetype and description, at least one hero and one texture query, and a `#rrggbb` pattern (`lib/schema.ts:307-318`); the copy states none of these. A reply that the provider accepts as valid against the copy is then rejected at `interpret.ts:180`, retried, and after the second attempt the whole lane is dropped (and M2 reports it as a missing key). The comment at line 84 shows that the enum was derived to prevent this, but the bounds were not. The installed zod 4.4.3 has `z.toJSONSchema`; run on `aiResponseSchema` it emits `minItems`, `maxItems`, `minLength` and `pattern`. `STRUCTURE_SCHEMA` (`structureAI.ts:31`) is a second hand-written copy, in sync today. **Fix:** derive both schemas with `z.toJSONSchema`, or add the missing bounds to the copy by hand. Whether Gemini's `responseJsonSchema` and OpenRouter accept every emitted keyword (`$schema`, `default`, `pattern`) needs a run with a key (`npm run eval:ai`). (#177)
- **M8** `lib/extract/palette.ts:156` — The area pass converts every sampled pixel to Lab and scans all canonical colors for it, although a screenshot holds few distinct colors. **Rule:** react-best-practices: `js-cache-function-results`. **Why:** measured on the three committed captures, this loop takes 108-204 ms for about 300,000 pixels, which is most of `extractPalette` (153-213 ms). A cache keyed by the 24-bit RGB value gave identical credits in 5-41 ms (about 3,000 distinct values per capture). The work is synchronous on the server's one thread, and a page at the 12-viewport panorama cap samples about 3.1 million pixels, ten times as many. The image lane already keeps color math out of its pixel loop (`imagePalette.ts:81-106`). **Fix:** keep a `Map<number, number>` from the RGB key to the nearest canonical index (or -1) for the duration of the call, and compute Lab only on a miss. The result does not change, so `npm run eval` must print the same scores. (#178)

(#179)

## What's Good

- **Compiler and lint**: `strict` is on with every flag of the family (resolved with `tsc --showConfig`). There is no explicit `any`, no `@ts-ignore` or `@ts-expect-error`, and the only three `eslint-disable` lines are for `<img>` elements that show data URLs. Five stricter compiler flags give 0 errors.
- **Model output is never trusted**: `parseJsonLoose` returns `unknown`, and all three AI lanes pass the result through `safeParse` before use (`interpret.ts:180`, `structureAI.ts:174`, `structureFromImage.ts:105`).
- **Type guards tell the truth**: every type guard in the code checks what it claims (for example `interpret.ts:246`, `page.tsx:102`, `recipes.ts:119`, `recipes.ts:164`, `structureFromImage.ts:198`).
- **Exhaustiveness by table**: lookups over a union are `Record<Union, …>` (`ROLE_USAGE`, `RECOMMENDED_TYPE_RANGES`, `SEMANTIC_HUE_BANDS`, the predicates of `findBand`), so a new member fails to compile. No `switch` over a union exists.
- **React**: the page has no effect; all interaction logic is in event handlers. Updates that depend on earlier state use the functional form (`page.tsx:105`, `:109`, `:154`). Every `&&` in the JSX has a boolean, object or string condition, so none can render `0` or `NaN`. The lists are a dozen items at most, so memoization and `content-visibility` would buy nothing.
- **Bundle**: the page imports types only from `lib/schema` and takes `emitTailwindTheme` from its own module (DIST-071); the built page chunk contains neither zod nor js-yaml (searched in `.next/static/chunks`).
- **Concurrency where it was already considered**: the image path runs its two model calls, the media-type sniffing and the per-image quantization under `Promise.all`.
- **Sorting**: every in-place `.sort()` acts on an array created in the same function, so none mutates shared state.
