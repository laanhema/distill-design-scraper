# Orchestration entry points (`lib/analyze.ts`)

`extractFromCapture(capture)` runs the **measured** design-tokens lane only (palette → typography → spacing/radius/elevation → recipes → states → motion) — browser-free, so the eval harness can replay a cached capture offline. It also consumes the optional second-pass capture fields when present: `responsiveHarvests` (mobile heading sizes → `sizePxMobile` via `applyMobileTypeSizes`), `darkCapture` (→ `extractDarkPalette`, which emits `paletteDark` only when backgrounds actually shift vs. the light palette — single-scheme sites get nothing), and `panoramaShot` (used *instead of* the viewport shot for the palette's area-weight pixel pass, so below-the-fold colors count — the panorama already contains the fold, so the two are never summed, which would double-count above-the-fold pixels). `extractStructureFromCapture(capture, report?)` runs the structure lane (pass the already-built `report` in `both` mode to enable the component→token cross-link). `enrichWithAI(measured, screenshots[])` is the separate, optional AI enrichment pass — merges `identity`/`imageMood` and Stage-E color-role refinements onto an already-measured report, and falls back to the measured report untouched if no API key is set or the model fails. `analyzeUrl` / `analyzeImages` are the full pipelines (render → measured → AI) that the API route calls. Both skip `enrichWithAI` entirely in `mode: "structure"` (nothing would consume it); for a URL, enrichment sees the viewport shot plus up to 3 evenly subsampled `scrollShots` tiles. On the URL path, `analyzeUrl` runs token AI enrichment (`enrichWithAI`) and Track B Stage 7 structural labelling (`extractStructureThroughStage7`) concurrently via `Promise.all` (#175), then feeds the resulting enriched report into `finalizeStructure` for Stages 8a/8b token linking. `analyzeImages(images, mode)` additionally runs the vision structure lane (`structureFromImages`) when `mode` is `structure`/`both`, returning `structureReport` plus a `structureUnavailableReason` when structure was requested but couldn't be produced.

This split (measured lane vs. AI lane) is intentional and load-bearing: **never** make `extractFromCapture` reach for the network or an API key. The measured lane must stay replayable offline for eval.

Every AI-backed lane (`lib/interpret.ts`, structure Stage 7 in `structureAI.ts`, and `structureFromImage.ts`) shares `lib/aiLane.ts` — the only file allowed to call a model provider. It owns the default model id, the `aiLaneAvailable()` key check, the `callModel` round-trip, the `parseJsonLoose` extractor (JSON-mode output, falling back to an outermost-brace match; never a shape validator — Zod stays the gate at each call site), the `retryOnce` retry-then-graceful-`null` policy, and `warnAiFailure` (classifies 429/quota vs. 400 vs. other in the log line). The interpretation lane generates the schema it sends from that same Zod gate — `OUTPUT_SCHEMA = z.toJSONSchema(aiResponseSchema)` in `lib/interpret.ts` (#177) — so the provider is told the bounds the gate checks (3–6 adjectives, non-empty archetype/description, at least one hero and one texture query, the `#rrggbb` pattern) and the two can't drift; `STRUCTURE_SCHEMA` in `structureAI.ts` is still a hand-written mirror of `aiStructureResponseSchema`. Told is not enforced, though: the schema is sent non-strict, so the routed model may ignore a bound, and Zod stays the only gate. Don't inline a model id, API call, availability check, or JSON scrape in a new AI call site.

**One provider, one seam.** `callModel` sends every round-trip to OpenRouter's `/chat/completions` (model from `OPENROUTER_MODEL`, default `google/gemini-3.5-flash`; images as `data:` URLs; `jsonSchema` sends a real, non-strict `response_format: json_schema` — not `strict: true`, because `STRUCTURE_SCHEMA`'s dictionary-shaped `additionalProperties` fields aren't representable under strict mode). `aiLaneAvailable()` is true only when `OPENROUTER_API_KEY` is set, and a `GEMINI_API_KEY` is not read (#199). There is no thinking cap: `ModelCall` has no such field and the request carries only `max_tokens`, so a lane's `maxOutputTokens` has to hold the routed model's thinking prelude and its answer. Zod remains the actual shape gate, since `parseJsonLoose` never validates shape.
