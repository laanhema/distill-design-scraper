# Design-tokens lane (Track A)

1. **`lib/extract/styleDump.ts`** — the single DOM-observation primitive. Its main pass is a self-contained `page.evaluate` callback (no imports allowed inside it — plain DOM APIs only) that walks every visible node once and returns a flat `StyleDump`: one `NodeStyle` record per node with per-channel colors (`background`/`text`/`border`/`fill`/`stroke`), layout (margins/paddings/gaps/radius/shadow), typography (only when the node has a _direct_ non-whitespace text child), an `interactive` flag, ARIA-derived `semanticContext` (`alert`/`invalid`), CSSOM-derived `:hover`/`:focus-visible` deltas (`states`), and declared `motion` (parsed `transition`/`animation` shorthand) plus dump-level `keyframes`. Every other extractor in the design-tokens lane consumes this dump — it is never re-walked.

   A **second pass** then repairs what CSSOM can't see: rules from cross-origin stylesheets throw on `.cssRules`, so the first pass reports their `href`s, and `styleDump` requests all of them at once through `page.context().request.get`, each under `CROSS_ORIGIN_SHEET_TIMEOUT_MS` (5 s). The texts are then applied one at a time in stylesheet order, whatever order the responses arrived in: each is re-parsed in a detached document, its selectors are re-matched against the live DOM via the temporary `data-distill-id` attribute, and any new hover/focus changes and `@keyframes` are merged into the dump. The requests live in a `CrossOriginSheetCache` that `capturePage` creates once per capture and passes to both style dumps, so the dark-scheme dump re-parses the text that the light dump fetched and no sheet is downloaded twice. It's best-effort per stylesheet (a sheet that fails or times out is remembered as failed for the capture and skipped, with no retry; a timeout also logs one `console.warn` per analysis that names the sheet's URL and the timeout, while a non-ok status, an empty body or a refused connection is skipped without a log line) and merge-only — it never overwrites a value the in-page pass already measured, and the first sheet that declares a change wins. So `styleDump` is `async` and does touch the network on the *render* path; the extraction lane it feeds still doesn't. `npm run eval` never runs this pass; `verify.sh drive cross-origin` (the verify skill) checks it end to end against a page whose sheets come from a second origin, one of which never answers the refetch.
2. **`lib/extract/palette.ts`** — the staged, score-based role-assignment pipeline: collect & channel-attribute colors → merge near-duplicates by perceptual ΔE (`MERGE_DELTA_E`) → area-weight against screenshot pixels via `sharp` (the stitched panorama when present, else the viewport shot — never both) → score every (color, role) pair (`backgroundScore`/`textScore`/`brandScore`/`borderScore`/`mutedScore`/`semanticScore`) → resolve with guardrails in `assignRoles` (e.g. `MIN_TEXT_CONTRAST` WCAG floor). **Order of the `pick()` calls in `assignRoles` matters**: semantic roles (`success`/`warning`/`danger`) are claimed _before_ the generic `surface`/`primary` scorers run, because `pick()` skips already-taken canonicals — a color with real usage-context evidence (an `alert`/`invalid`-flagged node + matching hue band) must lock in its semantic role first, or a broader role will grab it by default when nothing else was competing. All color math is perceptual (Lab/OKLCH via `lib/color.ts`), never raw RGB.
3. **`lib/extract/typography.ts`**, **`lib/extract/tokens.ts`** (spacing/radius/elevation) — deterministic aggregation off the same dump.
4. **`lib/extract/recipes.ts`** — groups dump nodes into element classes (Button/TextLink/NavItem/Input/Card/Badge) and takes the _modal_ observed value per property, so one outlier instance can't skew a recipe; colors resolve to palette-role names via nearest-ΔE match, falling back to raw hex rather than fabricating a role.
5. **`lib/extract/states.ts`** — attributes each node's CSSOM hover/focus deltas to the palette role of that node's _own_ base color, aggregated (again, modal) across every node sharing a role.
6. **`lib/extract/motion.ts`** — attributes each node's declared transitions/animations to the same recipe element classes (it reuses `recipes.ts`'s exported `classify`, so a node that isn't a recognized element class contributes no motion), dedupes identical entries, and keeps only the `@keyframes` definitions actually referenced by an emitted animation. No entries → the whole `motion` section is omitted.
7. **`lib/extract/roleMatch.ts`** — the one shared "nearest palette role for a measured color" helper (ΔE-based, not exact-hex). Both `recipes.ts` and the structure lane's `tokenLink.ts` use this; don't reintroduce a third inline copy of this match. Likewise **`lib/extract/mode.ts`** is the shared modal-value helper (first-seen wins ties) used by `tokens.ts` and `typography.ts`. (`recipes.ts` keeps its own keyed `modal<T>` for objects.)
8. **`lib/extract/imagePalette.ts`** — the image-input counterpart to `palette.ts`: pixel-quantizes each uploaded image into ΔE-merged clusters, then merges clusters _across_ images before role assignment (so multi-image uploads yield one coherent palette, not N colliding ones).
9. **`lib/extract/palette.ts` also exports `extractDarkPalette`** — runs the palette pipeline on the dark-scheme dump and compares backgrounds against the light palette by ΔE; if they didn't shift, it returns nothing (no fake dark palette for single-scheme sites).
