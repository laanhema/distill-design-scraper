# API route (`app/api/analyze/route.ts`)

Accepts `url` or `images: { data, name? }[]` (capped at `MAX_IMAGES = 6`; the AI lane further caps what it sends to the model at `MAX_INTERPRET_IMAGES = 4` in `lib/interpret.ts` — the measured palette merge still uses all 6), plus `mode` (defaults to `"both"`); `image`/`imageName` survive as a deprecated single-image alias that's _merged_ into `images`, not replaced by it. The cache key hashes all image payloads. A URL response carries `meta.viewportShots`: the viewport shot, then the panorama when present, each once, as PNG data URLs. An image response carries no screenshots: the uploads are neither sent back to the client that sent them nor held in the cache, and `app/page.tsx` shows the previews it held at submit instead. The singular `viewportShot` was removed in #179.

Bodies over `MAX_REQUEST_BODY_BYTES` (sized from `MAX_IMAGES` × the per-image payload cap) get a 413 before parsing. Responses are cached in `lib/cache.ts` — a 10-minute TTL keyed by SHA-256 of the request, bounded like the rate limiter (`CACHE_MAX_ENTRIES` cap, expired-sweep then LRU eviction, plus an `unref()`d periodic sweep); both read their env caps through `lib/env.ts`'s `parsePositiveNumber`/`parsePositiveInteger`, which fall back to the default on invalid or non-positive values.

Rate limiting sits _after_ the cache check on purpose: cache hits consume zero budget, only requests about to trigger a Chromium render or AI call count, and a limited request gets a 429 with a `Retry-After` header. Image responses in `structure`/`both` mode carry `structureReport` (vision-inferred) and, when structure was requested but failed, `structureUnavailableReason` — and a response with a transient structure failure is deliberately _not_ cached, so a retry can succeed. URL responses follow the same rule: if structure extraction throws, the response carries `structureUnavailableReason` and isn't cached.
